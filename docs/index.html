qod_qdrant

Query Qdrant collections from DuckDB, with SQL.

Attach a Qdrant instance, read its collections as tables, and rank them with dense, keyword (BM25) or hybrid search, all in the same SELECT that joins your other data.

DuckDB 2.0.1 Qdrant 1.20.2 C++ extension MIT
Example points. Drag, or use the arrow keys. 
SELECT title, _qod_score
FROM qod_search('kb.main.docs',
  query := qod_dense('title_dense', [0.62, 0.41]),
  k := 5);

What it does

Each collection you declare becomes a DuckDB table. A plain scan reads its points; qod_search asks Qdrant for the top k and returns them as rows you can filter, join and aggregate.

SELECT * FROM kb.main.docs

Collections as tables

Declared payload fields are typed columns (VARCHAR, BIGINT, BOOLEAN, DOUBLE). Point ids and scores come back as _qod_id and _qod_score.

qod_dense · qod_bm25 · qod_rrf

Dense, keyword and hybrid

Search by vector, by BM25 keywords computed by Qdrant itself, or fuse several branches with reciprocal rank fusion in one request.

filter_sql := 'status = ''active'''

Filters run in Qdrant

Equality tests, IN lists, AND and OR become a Qdrant filter, so k counts only the rows you asked for. A condition it cannot translate is refused with an error.

"options": {"language": "french"}

BM25 in your language

Each keyword index declares the Qdrant options it was built with. Index the same text twice, French and English, and fuse both in one query.

request := '{"query": ...}'

Raw Qdrant requests

Send a Qdrant query body when SQL helpers are not enough: RRF weights, formulas, MMR. Inside QoD, every request is checked against row and column policies first.

CREATE SECRET (TYPE qdrant, ...)

Strict by default

Unknown config keys are refused, error messages name the path and the rule but never a value, keys live in DuckDB secrets, and TLS is always verified.

Quick start

Until the community listing is live, build it from source: git clone --recurse-submodules https://github.com/starlake-ai/qod_qdrant, then GEN=ninja make release, and load build/release/extension/qod_qdrant/qod_qdrant.duckdb_extension in a DuckDB started with -unsigned.

Install and load

-- once published to DuckDB community extensions
INSTALL qod_qdrant FROM community;
LOAD qod_qdrant;

Store the API key as a secret

CREATE SECRET q (TYPE qdrant, API_KEY 'your-qdrant-key');

A persistent secret (CREATE PERSISTENT SECRET) is stored unencrypted on disk by DuckDB. Prefer a temporary one, or an environment variable you read yourself.

Attach a collection

ATTACH 'qdrant:docs' AS kb (TYPE qdrant, SECRET q, READ_ONLY, CONFIG '{
  "endpoint": "https://qdrant.example.com:6333",
  "apiKeySecret": "QDRANT_API_KEY",
  "guarantee": "filtered_retrieval",
  "collections": [{
    "schema": "main", "table": "docs", "collection": "kb_docs",
    "generation": 1, "schemaVersion": 1,
    "fields": [
      {"name": "title",  "path": "title",  "type": "VARCHAR", "required": false},
      {"name": "body",   "path": "body",   "type": "VARCHAR", "required": false},
      {"name": "status", "path": "status", "type": "VARCHAR", "required": true}
    ],
    "vectors": [{"name": "title_dense", "dimensions": 768, "datatype": "float32",
                 "dependsOn": ["title"], "modelVersion": "e5-large-v2@1"}],
    "sparseVectors": [
      {"name": "body_fr", "model": "qdrant/bm25", "dependsOn": ["body"],
       "options": {"language": "french"}},
      {"name": "body_en", "model": "qdrant/bm25", "dependsOn": ["body"]}
    ]
  }]
}');

Search

-- keyword search in French and English, fused, only active documents
SELECT title, _qod_score
FROM qod_search('kb.main.docs',
  query := qod_rrf([
    qod_bm25('body_fr', 'résiliation du contrat'),
    qod_bm25('body_en', 'résiliation du contrat')
  ]),
  filter_sql := 'status = ''active''',
  k := 10);

Config reference

The CONFIG of an ATTACH is one JSON object. Unknown keys are refused, and every error names the JSON path and the rule, never the value.

KeyWhat it holds
endpointThe Qdrant origin, https://host[:port], no path.
apiKeySecretThe name of the secret that holds the API key, [A-Z][A-Z0-9_]{0,63}. A literal key in the config is refused.
guaranteeexact_isolated (the default) or filtered_retrieval. Keyword and hybrid searches with a keyword branch run only under filtered_retrieval.
collections[]1 to 64 entries, each a table: schema, table, the Qdrant collection, generation and schemaVersion (integers, 1 or more).
…fields[]The payload fields read as columns: name, path in the payload, type (VARCHAR, BIGINT, BOOLEAN, DOUBLE), required.
…vectors[]Dense vectors: name, dimensions, datatype (float32), dependsOn (the fields it was computed from), modelVersion.
…sparseVectors[]0 to 8 keyword (BM25) indexes: name, model (qdrant/bm25), dependsOn. The collection declares the vector with modifier: idf.
…sparseVectors[].optionsOptional. The Qdrant BM25 options the index was built with, sent with every keyword query on it. Any key is accepted and copied as written; without it, Qdrant's defaults apply (English).

BM25 options

What Qdrant's qdrant/bm25 model reads from options:

language
Stemming and stopwords for that language, english by default.
stemmer
Set apart from the language, or {"type": "none"} to turn it off.
stopwords
Words to drop, merged with the language's own set.
tokenizer
How text is split into words.
ascii_folding
true matches words with and without accents.
k, b, avg_len
BM25's scoring parameters.

Match them to the indexing

Qdrant applies these options when it builds the index and again when it reads a query. Declare exactly what your loader used: Qdrant checks neither the keys nor the values, and a mismatch only shows as missing results.

-- the same text, indexed twice
{"name": "body_fr", "model": "qdrant/bm25",
 "dependsOn": ["body"],
 "options": {"language": "french", "ascii_folding": true}}
{"name": "body_en", "model": "qdrant/bm25",
 "dependsOn": ["body"]}

SQL reference

NameWhat it is
qod_search(relation, query := ..., filter_sql := ..., k := ...)Table function: the top k points of a declared table, best first, with every declared column, _qod_id and _qod_score.
qod_search(relation, request := '<json>', k := ...)The same with a raw Qdrant points/query body instead of query.
qod_dense(vector_name, vector)A dense branch: the query vector, checked against the declared dimensions.
qod_bm25(vector_name, text)A keyword branch: Qdrant tokenizes the text with the index's declared options.
qod_rrf([branches], prefetch_k := ...)Reciprocal rank fusion of two or more branches, dense or keyword.
_qod_id, _qod_scoreThe point id (decimal or UUID text) and Qdrant's score. Scores of dense, keyword and hybrid searches are not comparable with each other.

Good to know

  • BM25 options must match the ones used when the collection was indexed; Qdrant does not check them, and a mismatch silently loses matches.
  • RRF uses Qdrant's default constant unless a raw request sets rrf.k or weights.
  • Keyword statistics are computed per shard, so a document's score depends on its shard.
  • Sources are read-only; the extension never writes to Qdrant.
  • Budgets cap k, request and response size, deadline, concurrency and prefetch depth, each a DuckDB setting.
  • Endpoints must be HTTPS; plain HTTP is planned for loopback hosts only, for local development.
